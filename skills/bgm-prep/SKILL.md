# 备团配乐（bgm-prep）

输入是**场景清单**（一行一段），输出是「场景 → 歌」的表 + 网易云歌单。
机器只负责捞候选和排序，**定选永远由人做**。

## 开工前要知道的三件事

1. **目标（target）= music2emo 的 56 个原生英文标签 + 权重**。不是中文概念，权重会自动归一化，最多 6 个。
2. **词表以 `$DSH_HOME/bgm-prep/moods.json` 为准**；读不到时用本 skill 同目录的 `moods.json` 快照。
   **不要读插件源码去推词表**——那是重复劳动，而且可能是旧版本。
3. 曲目表是 schema 2，路径惯例 `<模组目录>/bgm/<scope>.cues.json`。所有写操作走工具，不要手改文件。

## 默认做到哪一步

用户说「整理模组歌单 / 剧本歌单」且没有额外说明时，**默认一路做到工作台里能看到带得分和概率的候选**：

1. 建表：`bgm_init`
2. 找候选：`bgm_fetch`
3. **分析听感：`bgm_tag`** —— 不做这步，工作台里就没有得分和标签概率
4. 用 `bgm_view`（`scope: "full"`）确认候选都有 `analysis`，再告诉用户打开「配乐工作台」：
   每段候选已按段内得分排序，每行显示得分 + 概率最高的两个标签

**默认停在这里**：候选可见、带得分与概率。**不自动定选、不自动建歌单**——那是人做的。

只有这几种情况提前停，并说明原因：

- 用户明确说「只要清单 / 先别找歌 / 不用分析」；
- 登录失效或检索不可用 → 停在建表；
- music2emo 环境不可用 → 停在候选，并明确说「分析未做，工作台里不会有得分」。

## 流程

### 1. 建表：`bgm_init`

- 一行一段：`scene` 必填；`trigger` 一句话上下文；纯调查/闲聊段给 `need_bgm: false`。
- **target 可以先不写**：工具会按中文描述自动预填 3–6 个标签。
- 返回后先看两样：
  - `unmatched`：**描述未命中标签**的段——这些段目标暂时是 `calm`，需要手写 target；
  - `dropped`：你写了词表外的标签，已被丢弃。

### 2. 需要手写 target 时

- 从 `moods.json` 的 56 个词里挑 **3–6 个**，权重写正数即可（会自动归一化）。
- 中文感受没有对应词时，用组合表达。例：
  - `恐怖` → `dark` + `dramatic` + `heavy`
  - `温馨` → `soft` + `hopeful` + `love`
  - `废墟` → `calm` + `space` + `sad`

  这是「用现有坐标表达一个感受」，不是特殊规则；所有中文词都同样处理。
- 不要把中文当标签，不要发明模型不认识的词。

### 3. 找候选：`bgm_fetch`

- 一次最多 8 段，每段留 8 首。
- 候选不够/不对味时，把 `wants` 里的中文检索词换一个再 `force: true` 重试，而不是硬选。
- 候选是工具从网易云搜来的；**你没有资格自己写歌名或 song_id**。

### 4. 分析听感：`bgm_tag`

- **默认必做**：不做这一步，工作台里只有歌名，没有得分和概率。
- 调 music2emo，按歌缓存；首次一首约 30–40 秒。
- **结果入库**（`$DSH_HOME/bgm-prep/analysis.db`）：同一首歌以后直接取，不会再分析；
  换一份曲目表、换一个会话也一样。
- 输出：56 个概率 + valence/arousal + 段内得分。
- 拿不到音频的候选标失败，但仍可试听；在交付说明里点出来。

### 5. 看表并交付：`bgm_view`

- `scope: "cues"` 只看切分；`"full"` 看完整表（含得分和概率）。
- 确认每段候选都有分析结果后，让用户打开工作台：
  **得分 + 概率最高的两个标签都已经在每行里**。
- 每段一行目标标签，`[描述未命中标签]` 的段要找补。

### 6. 人定选

- 让用户在工作台试听（完整播放器），或用户直接给 `song_id`。
- `bgm_pick` 的 `song_id` **必须来自该段 candidates**，否则整条被拒绝。
- `why` 写具体特征，30 字以内；不要写「好听」「合适」这种空话。

### 7. 出歌单：`bgm_commit`

- 幂等：同名歌单会复用，只补没加过的曲子。
- 同时导出 `review.md` / `playlist.txt` / `playlist.csv`。

## 规则

| 规则 | 说明 |
|---|---|
| **默认端到端** | 说「整理歌单」就一路做到候选**带得分和概率可见**；不要停在「只建了表」或「只找了候选」 |
| 候选只能来自工具 | 不许凭记忆写歌名；`bgm_pick` 会校验 |
| 每段 3–6 个标签 | 超过 6 个会被截断 |
| 只在段内排序 | 得分是「按这段权重算的」，不要跨段比 |
| 差不多就好 | 目标是在 8 首里大致排对，不是判对情绪 |
| 一次 10–20 段 | 超过就拆 scope，别把一整个战役塞一张表 |
| 不读插件源码 | 词表在 `moods.json`，用法在本 skill |
| 不自动拆模组 | 场景由用户提供；你只负责整理和调用工具 |
| 不替人做最终选择 | 得分只是排序参考；定选和建歌单要等人发话 |

## 收尾检查

- 每段候选都做过分析了吗（`analysis.probs` 存在，或已明确说明失败）；
- 工作台打开后，每行能看到「得分 x.xx + 两个标签概率」吗；
- `unmatched` 的段补齐 target 了吗；
- 每段状态：已选 / 待选 / 不配乐；
- 歌单里的曲目顺序 = 场景顺序（等用户定选后才建）。
