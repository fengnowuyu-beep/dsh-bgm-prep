# 跑团配乐·备团

## 它解决什么

备团时把「这局有哪几个场面」变成「每个场面放哪首」。做了三件事：

1. 把场景整理成一份带标签的**曲目表**（张力、明暗、能量、织体、人声）
2. 在候选池里为每段定一首主用曲 + 最多两首备选，并写一句具体理由
3. 导出成可照着建的歌单清单

## 它不做什么

- 不做开团时的播放（工作台只是备团期的试听工具，开团请用你自己的播放器）
- 不重新分发音频：试听走本机转发直链，分析用的音频只缓存在本机
- 不自动建歌单（开放平台没有歌单写入接口，`bgm_commit` 只导出清单）
- 不读 PDF/图片模组（原文由用户粘贴或另存为文本）

## 六个工具

| 工具 | 作用 |
|---|---|
| `bgm_init` | 建立/更新曲目表，只写场景与标签（含 `target` / `avoidTargets`） |
| `bgm_fetch` | 检索候选（歌单为主 + CLI 搜歌补充），写回曲目表 |
| `bgm_tag` | 调 music2emo 做听感分析，写回 56 维概率与 V/A |
| `bgm_pick` | 提交选曲；`song_id` 不在候选里会被拒绝 |
| `bgm_view` | 只读查看场景表或曲目表 |
| `bgm_commit` | 导出 review.md / playlist.txt / playlist.csv |

## 负向标签（avoidTargets）

每段可以给 3–5 个「要压低的标签」（如 `happy` / `upbeat`），与正向 `target` 独立：

- 权重按实际数量归一化，打分用乘性惩罚 `base × (1 − 0.6·Σ w⁻·p)`，最多压到基础分的 40%；
- 不剔除候选、分数不为负；每个标签独立计分（不去重、不合并）；
- 能被 `avoids` 文本映射成标签的（「欢快」）会自动转过来；映射不到标签的（「人声」）走标题关键词或标「无法验证」；
- 工作台每段有编辑区，可增删、直接改权重；设置里可以一键关掉（`settings.json` 的 `avoidEnabled`）。

## 人声识别（CLAP 零样本）

- 每首分析完情绪后，用 CLAP 判断「器乐 / 有人在唱」，取全曲 **6 个固定 10 秒窗口**里最大的概率，
  写进 `analysis.vocal`（0–1）。固定 10 秒是为了绕开 CLAP 特征提取器的随机截断（同一文件每次结果一致）；
  本地权重缓存，断网可用，每首约 0.4 秒（GPU）。
- 打分时按 `cue.vocal` 乘性压低：`none` 全额、`any` 半额、`wordless` 不罚；
  `factor = 1 − penalty × 档位 × (p − threshold) / (1 − threshold)`，档位取 1.0 / 0.5 / 0，默认 `penalty=0.6`（扣减上限）、`threshold=0.1`（起罚线）；两者都能在工作台设置里调。
- 工作台候选卡片会显示「人声 0.71 → ×0.78」；设置里可关闭探测与惩罚（`analysis.vocal.enabled`）。
- 存量分析会自动补算人声概率（只跑 CLAP，不重算情绪）。

## 数据放在哪

- 曲目表：`<模组目录>/bgm/<scope>.cues.json`（跟着模组走）；测试用的表在 `test-runs/`
- 凭据、token、缓存：`$DSH_HOME/bgm-prep/`
- 听感结果：`$DSH_HOME/bgm-prep/analysis.db`（一首歌只分析一次，所有表共用）
- 解码后的音频：`$DSH_HOME/bgm-prep/cache/audio/`（默认上限 5 GB）
- 可调参数：`$DSH_HOME/bgm-prep/settings.json`

## 使用前提

需要本机 `ncm-cli` 完成一次扫码登录（`node scripts/setup.mjs --cli-login`），
检索、歌单、播放直链都走它；开放平台凭据（AppID + PrivateKey）是可选路径。
配置方式见插件目录下的 `README.md` 的「一次性配置」。

## 已知限制

- 开放平台 HTTP 的 `search/song` 接口被应用权限拒绝（300）；检索改走「歌单为主 + ncm-cli 搜歌补充」，
  所以搜歌本身是可用的，只是不能走 HTTP 那条路
- 没有歌单写入接口，最后一步需手动建歌单（约 3 分钟）
- 分析粒度固定：整首按 **30 秒不重叠**切段、各段等权平均，**尾段不足 30 秒会丢弃**；
  和弦分支整首跑、**只取前 100 个和弦事件**；`stability` 恒为 `null`
- 前奏静音无法自动判断（`intro_unknown` 恒为 true）
- 人声识别是零样本二分类，不是专用分类器：器乐基本能压得住（实测 <0.1），
  但副歌不明显的歌会偏低（实测「小半」0.47、「如果呢」0.32），需要人工复核边界样本

详细的操作规则见 `docs/WORKFLOW.md`。
